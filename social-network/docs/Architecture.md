# Social Network Architecture

## Overview

This project is a Facebook-like social networking platform built using:

* Frontend: Vue.js
* Backend: Go
* Database: SQLite
* Realtime Communication: Gorilla WebSocket
* Authentication: Sessions & Cookies
* Containerization: Docker

The system follows a client-server architecture where the frontend communicates with the backend through REST APIs and WebSockets.

# Authentication Flow

Authentication is session-based.

## Registration

1. User submits registration form.
2. Password is hashed using bcrypt.
3. User record is stored in SQLite.

## Login

1. User submits credentials.
2. Password is verified.
3. Session is created.
4. Session ID is stored in a cookie.
5. Cookie is sent to browser.

## Authenticated Requests

```text
Browser
    │
Cookie(session_id)
    │
    ▼
Auth Middleware
    │
Session Validation
    │
    ▼
Protected Endpoint
```

# WebSocket Architecture

WebSockets are used for realtime communication.

## Private Chat

```text
User A
   │
   ▼
WebSocket Server
   │
   ▼
User B
```

Requirements:

* At least one user follows the other
  OR
* Recipient profile is public

---

## Group Chat

```text
Member A
Member B
Member C
     │
     ▼
Group Chat Room
```

Messages are broadcast to all connected group members.

# Security Considerations

* Passwords stored using bcrypt
* Session-based authentication
* Authorization checks on every protected route
* File upload validation
* Input sanitization
* SQL injection prevention through prepared statements
* Protected WebSocket connections

---

# Development Principles

1. Keep business logic inside services.
2. Keep SQL queries inside repositories.
3. Never access the database directly from handlers.
4. Protect every private route with middleware.
5. Use migrations for all schema changes.
6. Write reusable frontend components.
7. Keep WebSocket logic isolated from HTTP handlers.
8. Maintain separation of concerns across all modules.
